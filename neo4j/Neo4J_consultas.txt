### Consulta 1:
Devolver el nombre y la descripción de aquellos objetos que no se pueden crear
mediante una receta ni se pueden obtener de un monstruo y se utilizan para craftear
o mejorar algún arma.



MATCH (i:Item)
WHERE NOT EXISTS { (:Recipe)-[:PRODUCES]->(i) }
  AND NOT EXISTS { (:Monster)-[:DROPS]->(i) }
  AND (
    EXISTS { (:WeaponCraft)-[:NEEDS]->(i) }
    OR EXISTS { (:WeaponUpgrade)-[:NEEDS]->(i) }
  )
RETURN i.name AS nombre, i.description AS descripcion



Esta consulta parte de todos los nodos de tipo Item. Después aplica tres condiciones. 
La primera descarta los objetos que pueden ser generados por una receta, comprobando que no exista ninguna relación PRODUCES desde Recipe hacia ese Item. 
La segunda descarta los objetos que pueden obtenerse matando monstruos, comprobando que no exista ninguna relación DROPS desde Monster hacia ese Item. 
La tercera condición mantiene únicamente los objetos que sí se utilizan en algún proceso de fabricación o mejora de armas, es decir, aquellos que aparecen como destino de una relación NEEDS desde WeaponCraft o desde WeaponUpgrade.

Finalmente, la consulta devuelve el nombre y la descripción de esos objetos. 
En resumen, se buscan materiales que son necesarios para fabricar o mejorar armas, pero que no tienen una forma directa de obtención modelada en el grafo mediante recetas ni monstruos.



### Consulta 2:
El id de receta, nombre de los items usados como input y nombre del item generado
como output de las 5 recetas que más ganancias generan. La ganancia que genera
una receta es el valor total de los items que genera, menos el coste total de los items
que necesita. Todos los items que se usan en la receta no deben ser producidos por
otras recetas.



MATCH (r:Recipe)-[p:PRODUCES]->(output:Item)
MATCH (r)-[:NEEDS]->(input:Item)

WITH r,
     collect(input) AS inputs,
     output,
     p.amount AS outAmount

WHERE ALL(i IN inputs WHERE NOT EXISTS { (:Recipe)-[:PRODUCES]->(i) })

WITH r,
     output,
     outAmount,
     inputs,
     reduce(
       coste = 0,
       i IN inputs | coste + coalesce(i.value, 0)
     ) AS costeTotal

WITH r,
     [i IN inputs | i.name] AS itemsInput,
     output.name AS itemOutput,
     coalesce(output.value, 0) * coalesce(outAmount, 1) - costeTotal AS ganancia

RETURN r.id AS recetaId,
       itemsInput,
       itemOutput,
       ganancia
ORDER BY ganancia DESC
LIMIT 5



La consulta empieza buscando cada receta, el item que produce y los items que necesita como entrada. 

La relación PRODUCES se guarda en la variable p porque contiene la propiedad amount, que indica cuántas unidades genera la receta.

Después se agrupan todos los inputs de cada receta con collect(input). 
Esto es importante porque la condición del enunciado no debe aplicarse item por item, sino a la receta completa. 
Por eso se utiliza ALL: la receta solo se queda en el resultado si todos sus inputs cumplen que no son producidos por ninguna otra receta.

A continuación, se calcula el coste total de los inputs mediante reduce. Se recorre la lista de materiales de entrada y se va sumando su valor. 
Se usa coalesce para evitar problemas si algún item no tuviera valor registrado, tratándolo como 0.

Después se calcula la ganancia: valor del item generado multiplicado por la cantidad producida, menos el coste total de los inputs. 
Finalmente, se devuelven el id de la receta, los nombres de los items de entrada, el nombre del item de salida y la ganancia. 
El ORDER BY ordena las recetas de mayor a menor ganancia y LIMIT 5 se queda con las cinco mejores.




### Consulta 3:
El nombre y el tipo del arma que se puede craftear directamente y que más daño
hace de tipo fuego. Además, incluir los monstruos que se deben matar para crearla,
así como cualquier material extra que se necesario para fabricar el arma y que no se
obtiene matando dichos monstruos.




MATCH (:Element {name:'fire'})<-[d:DEALS]-(w:Weapon)<-[:PRODUCES]-(wc:WeaponCraft)

WITH w, wc, d
ORDER BY d.damage DESC
LIMIT 1

MATCH (wc)-[:NEEDS]->(i:Item)
OPTIONAL MATCH (m:Monster)-[:DROPS]->(i)

WITH w,
     collect(DISTINCT m.name) AS monstersRaw,
     collect(DISTINCT CASE WHEN m IS NULL THEN i.name END) AS extrasRaw

RETURN w.name AS nombre,
       w.kind AS tipo,
       [m IN monstersRaw WHERE m IS NOT NULL] AS monstruos,
       [e IN extrasRaw WHERE e IS NOT NULL] AS materialesExtra



La consulta empieza buscando armas que causan daño de tipo fuego y que además se pueden crear directamente mediante un WeaponCraft. 
Esto se consigue siguiendo el patrón Element fire <- DEALS - Weapon <- PRODUCES - WeaponCraft. La relación DEALS se guarda como d porque ahí está el daño elemental.

Después se ordenan esas armas por daño de fuego de mayor a menor y se usa LIMIT 1 para quedarse únicamente con el arma crafteable directamente que más daño de fuego hace.

Una vez elegida esa arma, se buscan los items que necesita su WeaponCraft. Para cada item se intenta encontrar opcionalmente un monstruo que lo dropee. 
Se usa OPTIONAL MATCH porque puede haber materiales que no los dropee ningún monstruo, y precisamente esos son los materiales extra.

Después se agrupan por separado los nombres de los monstruos y los materiales extra. 
El CASE WHEN m IS NULL THEN i.name END identifica los items que no tienen monstruo asociado. 
Al final se eliminan los posibles valores nulos de ambas listas y se devuelve el nombre del arma, su tipo, los monstruos necesarios y los materiales extra.




### Consulta 4:
Por cada tipo de arma, mostrar el nombre del arma o armas de ese tipo que más
daño combinado hace, es decir, la suma de su daño base más todos los daños extra
que sean de kind “element”. Devolver los tipos ordenados de mayor cantidad a
menor cantidad de daño y mostrar el daño que hace dicha arma.




MATCH (w:Weapon)
OPTIONAL MATCH (w)-[d:DEALS]->(:Element {kind: 'element'})

WITH w,
     coalesce(w.damage, 0) + coalesce(sum(d.damage), 0) AS dañoTotal

WITH w.kind AS tipo,
     max(dañoTotal) AS maxDaño,
     collect({nombre: w.name, daño: dañoTotal}) AS armas

RETURN tipo,
       [a IN armas WHERE a.daño = maxDaño | a.nombre] AS armas,
       maxDaño AS dañoCombinado

ORDER BY dañoCombinado DESC




Esta consulta calcula el daño combinado de cada arma. Primero se buscan todos los nodos Weapon. 
Después, con OPTIONAL MATCH, se buscan sus daños extra contra elementos de tipo element. 
Se usa OPTIONAL MATCH porque algunas armas pueden no tener daño elemental, pero aun así deben aparecer en el cálculo con solo su daño base.

Luego se calcula el daño total de cada arma sumando su daño base y la suma de todos sus daños elementales. Se usa coalesce para evitar que valores nulos afecten al cálculo.

Después se agrupa por tipo de arma. Para cada tipo, se calcula el máximo daño total con max(dañoTotal) y se guarda una lista con todas las armas de ese tipo y su daño. 
En el RETURN se filtra esa lista para devolver únicamente las armas cuyo daño coincide con el máximo del tipo. 
De esta forma, si hay empate entre varias armas del mismo tipo, se devuelven todas.

Finalmente, los tipos de arma se ordenan de mayor a menor daño combinado.





### Consulta 5:
El proceso necesario para obtener el arma con id 297. Dicha arma no se puede
craftear directamente, solo se puede obtener mediante actualización de otras armas.
La consulta debe devolver todas las armas intermedias que debo actualizar desde
un arma que sí sea crafteable directamente. Para el arma 297, dicho proceso es [297,
296, 295], es decir, se debe empezar creando el arma 295, luego actualizar el arma
295 a la 296 y por último actualizar la 296 a la 297.



MATCH path = (w2:Weapon {id:297})<-[:TRANSFORMS*]-(w1:Weapon)
WHERE EXISTS { (w1)<-[:PRODUCES]-(:WeaponCraft) }

WITH [n IN nodes(path) WHERE n:Weapon | n.id] AS weapons

RETURN weapons AS proceso




La consulta busca el proceso para llegar al arma con id 297 mediante relaciones TRANSFORMS. 
Se escribe el camino empezando desde el arma final y yendo hacia atrás hasta un arma base. 
La relación variable [:TRANSFORMS*] permite recorrer una o más relaciones de actualización.

La condición WHERE EXISTS comprueba que el arma inicial del camino se puede fabricar directamente, es decir, que existe un WeaponCraft que la produce. 
Esto es necesario porque el proceso debe empezar desde un arma crafteable.

Después se usa nodes(path) para obtener todos los nodos del camino. 
Como el camino puede incluir nodos que no son armas, se filtra con WHERE n:Weapon y se devuelve solo el id de las armas. 
El resultado final es la lista de armas del proceso, desde el arma objetivo hacia la base crafteable.





### Consulta 6:
El nombre de los monstruos que tengo que matar para fabricar el arma con id 880.
Ten en cuenta que dicha arma no se puede craftear directamente, solo se puede
obtener mediante actualización de otras armas.



MATCH path = (target:Weapon {id: 880})<-[:TRANSFORMS*]-(base:Weapon)<-[:PRODUCES]-(wc:WeaponCraft)

UNWIND [n IN nodes(path) WHERE n:WeaponCraft OR n:WeaponUpgrade] AS step

MATCH (step)-[:NEEDS]->(:Item)<-[:DROPS]-(m:Monster)

RETURN DISTINCT m.name AS monstruo
ORDER BY monstruo


La consulta busca qué monstruos hay que matar para fabricar el arma con id 880. 
Como esta arma se obtiene por actualización, se construye un camino desde el arma objetivo hacia atrás hasta un arma base que sí sale de un WeaponCraft.

Una vez encontrado el path, se extraen del camino los nodos que realmente necesitan materiales: WeaponCraft y WeaponUpgrade. 
Esto es importante porque los materiales no los necesitan directamente las armas, sino los procesos de creación o mejora.

UNWIND convierte esa lista de pasos de fabricación en filas individuales. 
Para cada paso, se buscan los items que necesita y los monstruos que dropean esos items. 
Finalmente, se devuelve el nombre de cada monstruo con DISTINCT para evitar duplicados, ya que un mismo monstruo podría dropear varios materiales necesarios.





### Consulta 7:
El arma con el proceso de fabricación más complejo, es decir, que se necesite pasar
por más armas intermedias para llegar a ella desde un arma que es crafteable
directamente. Debes devolver, el nombre del arma, el tipo del arma, el nombre de
todas las armas por las que debo pasar para llegar a ella y el número de pasos
necesarios.


MATCH path = (base:Weapon)-[:TRANSFORMS*]->(target:Weapon)
WHERE EXISTS { (:WeaponCraft)-[:PRODUCES]->(base) }
  AND NOT EXISTS { (:WeaponCraft)-[:PRODUCES]->(target) }

WITH target,
     [n IN nodes(path) WHERE n:Weapon | n.name] AS armas,
     size([n IN nodes(path) WHERE n:Weapon]) - 1 AS numero_de_pasos

ORDER BY numero_de_pasos DESC
LIMIT 1

RETURN target.name AS arma,
       target.kind AS tipo,
       armas AS armas_intermedias,
       numero_de_pasos


Esta consulta busca el arma con el proceso de fabricación más complejo. Para ello, se buscan caminos desde un arma base hasta un arma objetivo usando relaciones TRANSFORMS.
 La base debe ser crafteable directamente, por eso se comprueba que exista un WeaponCraft que la produzca. 
 Además, se excluyen como objetivo las armas que ya se pueden craftear directamente, porque la consulta se centra en armas que requieren un proceso de actualización.

Después, con nodes(path), se extraen solo los nodos Weapon del camino y se guardan sus nombres. 
El número de pasos se calcula como el número de armas del camino menos uno. Así se cuenta cuántas transiciones entre armas son necesarias.

Luego se ordenan los caminos de mayor a menor número de pasos y se usa LIMIT 1 para quedarse con el proceso más largo. 
Finalmente, se devuelve el nombre del arma objetivo, su tipo, las armas intermedias del proceso y el número de pasos necesarios.





### Consulta 8:
El arma con el proceso de fabricación que requiere matar más monstruos diferentes,
puedes obviar los empates. Debes devolver el nombre del arma, el nombre de todas
las armas por las que debo pasar para llegar a ella y el número de monstruos que es necesario matar.



MATCH path = (wc:WeaponCraft)-[:PRODUCES]->(base:Weapon)-[:TRANSFORMS*0..]->(target:Weapon)

UNWIND [n IN nodes(path) WHERE n:WeaponCraft OR n:WeaponUpgrade] AS step

MATCH (step)-[:NEEDS]->(:Item)<-[:DROPS]-(m:Monster)

WITH target.name AS nombre,
     [n IN nodes(path) WHERE n:Weapon | n.name] AS armas,
     collect(DISTINCT m.name) AS monstruos

RETURN nombre,
       armas,
       monstruos,
       size(monstruos) AS numero_monstruos

ORDER BY numero_monstruos DESC
LIMIT 1




Esta consulta busca el arma cuyo proceso de fabricación requiere matar más monstruos diferentes. A diferencia de otras consultas, aquí se usa [:TRANSFORMS*0..]. 
El 0 permite incluir también armas que se fabrican directamente sin ninguna actualización, es decir, el caso en el que base y target son el mismo arma.

El camino empieza en un WeaponCraft que produce un arma base y después puede continuar por cero o más actualizaciones hasta un arma objetivo. 
Luego se extraen del camino los nodos que necesitan materiales: WeaponCraft y WeaponUpgrade.

Con UNWIND se procesa cada paso de fabricación por separado. Para cada paso se buscan los items necesarios y los monstruos que los dropean. 
Después se agrupan los monstruos con collect(DISTINCT m.name), lo que asegura que cada monstruo se cuenta una sola vez aunque dropee varios materiales.

Finalmente, se devuelve el nombre del arma, la cadena de armas del proceso, la lista de monstruos y el número de monstruos distintos. 
Se ordena de mayor a menor número de monstruos y se usa LIMIT 1 para quedarse con el caso más exigente.





### Consulta 9:
Escribe una consulta que devuelva para cada ubicación (Location), el o los
elementos (Element) de tipo "element" frente a los que los monstruos que viven allí
son más débiles en conjunto (sumando los niveles de debilidad), y devuelve el
nombre de la ubicación, el valor total de esa máxima debilidad y los nombres de
dichos elementos.


MATCH (l:Location)<-[:LIVES_IN]-(m:Monster)-[w:WEAK_TO]->(e:Element {kind: 'element'})

WITH l,
     e.name AS elemento,
     sum(w.level) AS debilidadTotal

WITH l,
     collect({elemento: elemento, debilidad: debilidadTotal}) AS debilidades,
     max(debilidadTotal) AS maxDebilidad

RETURN l.name AS ubicacion,
       maxDebilidad AS debilidadMaxima,
       [d IN debilidades WHERE d.debilidad = maxDebilidad | d.elemento] AS elementos

ORDER BY ubicacion




La consulta calcula, para cada ubicación, frente a qué elementos son más débiles en conjunto los monstruos que viven allí. 
Primero se busca el patrón Location <- LIVES_IN - Monster - WEAK_TO -> Element, limitando los elementos a los de tipo element.

Después se agrupa por ubicación y elemento, sumando los niveles de debilidad con sum(w.level). 
Así se obtiene la debilidad total acumulada de los monstruos de una ubicación frente a cada elemento.

En el siguiente WITH se guarda una lista de pares elemento-debilidad y, al mismo tiempo, se calcula la debilidad máxima de cada ubicación. F
inalmente, en el RETURN se filtra la lista para devolver solo los elementos cuya debilidad coincide con esa máxima. 
Esta forma permite devolver varios elementos si hay empate.

La consulta termina ordenando las ubicaciones alfabéticamente.





### Consulta 10:
Escribe una consulta que, dado un tipo de arma como parámetro, devuelva qué arma
deberías llevar a cada localización. Para ello, se seleccionarán las armas del tipo indicado que causen más daño contra los elementos frente a los que, en conjunto,
los monstruos de esa localización son más débiles (sumando sus niveles de
debilidad). La consulta debe devolver el nombre de la ubicación, los elementos
frente a los que los monstruos son más vulnerables y el nombre de las armas
recomendadas.


MATCH (l:Location)<-[:LIVES_IN]-(m:Monster)-[weak:WEAK_TO]->(e:Element {kind: 'element'})

WITH l,
     e,
     sum(weak.level) AS debilidadTotal

WITH l,
     collect({
       elemento: e,
       nombre: e.name,
       debilidad: debilidadTotal
     }) AS debilidades,
     max(debilidadTotal) AS maxDebilidad

WITH l,
     [d IN debilidades WHERE d.debilidad = maxDebilidad | d.elemento] AS elementosVulnerables,
     [d IN debilidades WHERE d.debilidad = maxDebilidad | d.nombre] AS nombresElementos

MATCH (arma:Weapon {kind: $tipoArma})
OPTIONAL MATCH (arma)-[deal:DEALS]->(e:Element {kind: 'element'})

WITH l,
     nombresElementos,
     arma,
     sum(
       CASE
         WHEN e IN elementosVulnerables THEN coalesce(deal.damage, 0)
         ELSE 0
       END
     ) AS dañoContraElementos

WITH l,
     nombresElementos,
     collect({arma: arma.name, daño: dañoContraElementos}) AS armas,
     max(dañoContraElementos) AS maxDaño

RETURN l.name AS ubicacion,
       nombresElementos AS elementosVulnerables,
       [a IN armas WHERE a.daño = maxDaño | a.arma] AS armasRecomendadas

ORDER BY ubicacion



Esta consulta recomienda armas para cada localización, dado un tipo de arma como parámetro. 
Primero se calcula, igual que en la consulta anterior, qué elementos son los más vulnerables para los monstruos de cada ubicación. 
Para ello, se suman los niveles de WEAK_TO por ubicación y elemento, se obtiene el máximo y se guardan los elementos que alcanzan ese máximo.

Después se buscan las armas cuyo kind coincide con el parámetro $tipoArma. 
Para cada arma, se buscan opcionalmente sus relaciones DEALS hacia elementos de tipo element. 
Se usa OPTIONAL MATCH porque puede haber armas que no tengan daño elemental, pero aun así deben ser consideradas.

Luego se calcula el daño que cada arma hace contra los elementos vulnerables de la ubicación.
 Para ello, se usa un CASE: si el elemento del daño del arma está dentro de la lista de elementos vulnerables, se suma ese daño; si no, se suma 0. 
 Así se obtiene el daño útil del arma para esa localización.

Después se agrupan las armas por ubicación, se calcula el máximo daño útil y se devuelve la o las armas cuyo daño coincide con ese máximo. 
Esto permite tener en cuenta empates. Finalmente, se devuelve el nombre de la ubicación, los elementos vulnerables y las armas recomendadas, ordenado por ubicación.
